# DE003: Security audit log cleared

**Status:** experimental lab rule. **Priority:** high.

## Detection hypothesis
Windows Security channel event 1102 from Microsoft-Windows-Eventlog.

## Telemetry
Windows Security event **1102**, provider `Microsoft-Windows-Eventlog`. See [field mapping](../schema.md). Audit configuration and collector coverage must be verified before deployment.

## Investigation
Identify the actor and change ticket. Preserve forwarded logs. Review preceding sign-ins and processes; establish whether logging continued after the event.

Preserve event record IDs, source host, timestamps and original records. Document the disposition as authorized activity, suspicious activity, or insufficient evidence. Containment requires the organization's incident-response process; this lab takes no response actions.

## False positives and tuning
Authorized troubleshooting or a documented lab reset.

Baseline the affected host role and actor. Any exception should have an owner, narrow scope, ticket and expiry. The reference evaluator deliberately applies no hidden allowlists.

## Blind spots
Does not cover other event channels, log-file deletion, or collection outages. Clearing alone is not proof of malicious activity.

## Validation
See the named positive and negative scenarios in `data/scenarios.json`. Benign lookalikes that should still alert are documented in the validation report. Synthetic test success is not a production accuracy measurement.

## Reference
[T1685.005 — MITRE ATT&CK](https://attack.mitre.org/techniques/T1685/005/). Mapping describes a possible behavior, not a conclusion about attacker intent.
