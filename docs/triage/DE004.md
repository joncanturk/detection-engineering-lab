# DE004: Local user account created

**Status:** experimental lab rule. **Priority:** low.

## Detection hypothesis
Account creation event explicitly enriched as local by a trusted normalizer or asset inventory.

## Telemetry
Windows Security event **4720**, provider `Microsoft-Windows-Security-Auditing`. See [field mapping](../schema.md). Audit configuration and collector coverage must be verified before deployment.

## Investigation
Identify the creator and new account SID, validate the ticket, then check group additions and first logon. Escalate unexpected privileged persistence.

Preserve event record IDs, source host, timestamps and original records. Document the disposition as authorized activity, suspicious activity, or insufficient evidence. Containment requires the organization's incident-response process; this lab takes no response actions.

## False positives and tuning
Provisioning, helpdesk work, and approved break-glass account creation.

Baseline the affected host role and actor. Any exception should have an owner, narrow scope, ticket and expiry. The reference evaluator deliberately applies no hidden allowlists.

## Blind spots
Native 4720 does not provide account_scope. Unknown or domain scope does not match. This is a visibility rule and intentionally alerts on legitimate local account creation too.

## Validation
See the named positive and negative scenarios in `data/scenarios.json`. Benign lookalikes that should still alert are documented in the validation report. Synthetic test success is not a production accuracy measurement.

## Reference
[T1136.001 — MITRE ATT&CK](https://attack.mitre.org/techniques/T1136/001/). Mapping describes a possible behavior, not a conclusion about attacker intent.
