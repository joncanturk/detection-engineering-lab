# DE005: Member added to built-in Administrators

**Status:** experimental lab rule. **Priority:** high.

## Detection hypothesis
A member is added to the built-in Administrators group, identified by SID rather than its localized name.

## Telemetry
Windows Security event **4732**, provider `Microsoft-Windows-Security-Auditing`. See [field mapping](../schema.md). Audit configuration and collector coverage must be verified before deployment.

## Investigation
Resolve the member SID and actor. Confirm authorization, inspect recent account creation and subsequent privileged activity, and follow the incident playbook if unauthorized.

Preserve event record IDs, source host, timestamps and original records. Document the disposition as authorized activity, suspicious activity, or insufficient evidence. Containment requires the organization's incident-response process; this lab takes no response actions.

## False positives and tuning
Approved endpoint provisioning, support elevation and emergency administration.

Baseline the affected host role and actor. Any exception should have an owner, narrow scope, ticket and expiry. The reference evaluator deliberately applies no hidden allowlists.

## Blind spots
Does not cover Domain Admins, other privileged groups or non-Windows systems. A matching change can be legitimate; do not suppress all administrator activity.

## Validation
See the named positive and negative scenarios in `data/scenarios.json`. Benign lookalikes that should still alert are documented in the validation report. Synthetic test success is not a production accuracy measurement.

## Reference
[T1098.007 — MITRE ATT&CK](https://attack.mitre.org/techniques/T1098/007/). Mapping describes a possible behavior, not a conclusion about attacker intent.
