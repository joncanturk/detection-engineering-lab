# DE002: PowerShell encoded command switch

**Status:** experimental lab rule. **Priority:** medium.

## Detection hypothesis
A PowerShell or pwsh executable with a standalone -enc or -encodedcommand switch, case insensitive.

## Telemetry
Windows Security event **4688**, provider `Microsoft-Windows-Security-Auditing`. See [field mapping](../schema.md). Audit configuration and collector coverage must be verified before deployment.

## Investigation
Check the parent process, user, signer and execution context. Decode the argument as data in an isolated analyst workflow; never execute it. Correlate PowerShell and EDR logs.

Preserve event record IDs, source host, timestamps and original records. Document the disposition as authorized activity, suspicious activity, or insufficient evidence. Containment requires the organization's incident-response process; this lab takes no response actions.

## False positives and tuning
Approved deployment agents and administrators sometimes use encoded commands.

Baseline the affected host role and actor. Any exception should have an owner, narrow scope, ticket and expiry. The reference evaluator deliberately applies no hidden allowlists.

## Blind spots
Only two explicit switch forms are covered. Other abbreviations, quoting, renamed binaries and in-process PowerShell are out of scope. Missing command-line telemetry prevents a match.

## Validation
See the named positive and negative scenarios in `data/scenarios.json`. Benign lookalikes that should still alert are documented in the validation report. Synthetic test success is not a production accuracy measurement.

## Reference
[T1059.001 — MITRE ATT&CK](https://attack.mitre.org/techniques/T1059/001/). Mapping describes a possible behavior, not a conclusion about attacker intent.
